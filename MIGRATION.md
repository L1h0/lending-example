## Просмотр любого этапа

```bash
git fetch origin
git switch --detach origin/checkpoint/2026-10-11-08-final-style
npm run check
npm run dev
```

Для исходного сайта используйте `origin/backup/before-redesign-2026-10-11`.
Для редактирования создайте новую ветку от выбранного снимка, например:

```bash
git switch -c rollback/chosen-version origin/checkpoint/2026-10-11-07-sections-02-04
```

## Возврат файлов с сохранением истории

Сначала сохраните незакоммиченные изменения. В рабочей ветке восстановите выбранный снимок и создайте новый коммит:

```bash
git restore --source=origin/backup/before-redesign-2026-10-11 --staged --worktree -- .
git commit -m "Вернуть исходную версию лендинга"
```

Для возврата к промежуточной версии замените источник на нужную контрольную ветку.
Так история последующих изменений остаётся доступной, без `reset --hard` и принудительной отправки.

## Публикация

Перенос подготовлен в отдельной ветке. Для проверки в GitHub создайте pull request после отправки веток. `main` и действующий GitHub Pages не меняются до подтверждения владельца.
Сборка `npm run build` создаёт каталог `docs/`. Перед будущей публикацией нужно проверить источник Pages в настройках репозитория.
Метаданные `noindex` сохранены из согласованного макета. Решение об индексации принимается отдельно при публикации.
